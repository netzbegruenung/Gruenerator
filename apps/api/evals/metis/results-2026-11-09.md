## Decisions

| spec          | first run (models / LLM, overall) | final run (models / LLM, overall)          | switched?                                                  |

| docsTiebreak  | 100 % / 100 %                     | 100 % / 90 % (4 LLM timeouts)              | yes                                                        |

| editTarget    | 87.5 % / 100 % (before tuning)    | 96.9 % / 71.9 % (9 LLM timeouts at 900 ms) | **no**: the two runs disagree, see below                   |
| computeVerify | 88.5 % / 96.2 %                   | 88.5 % / 96.2 %                            | no: more than 5 points below, and the holdout is lower too |

**editTarget:** in the first run the LLM resolver answered every case correctly within its 900 ms budget. In the final run the intermediate lane was slow (p50 746 ms) and 9 of 32 calls ended in `null`. By the final run alone the decision model would qualify, by the first it would not. The rule is not applied after the fact on the more favourable run. If the timeouts show up in production logs too (`[EditTarget] … keines (…ms)` near 900 ms), that is the case for switching.

## Label review

Every miss was checked against its label. None was wrong:

- **"Mach den Text größer"** (sharepic + document): stays sharepic. Font size exists only on the graphic, and the case comes from the resolver's own header.
- **"Welches Dokument ist das älteste?":** praezision, because it sorts the sources by date (the same as "Sortiere die Quellen nach Datum").
- **The two dropped year filters** in computeVerify ("2025", "heuer"): unplausibel per the verifier's own rule ("Eine Einschränkung, die in der Frage ausdrücklich steht, fehlt im Code").
- **"durchschnittliche Spende pro Person"** with `groupby("Name").sum().mean()`: plausibel. It averages per person, as asked.

No label was changed.
